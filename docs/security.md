# الأمان ونموذج التهديدات

## التشفير

- **AES-256-GCM** لتشفير محتوى كل وثيقة.
- مفتاح عشوائي **(32 بايت)** لكل وثيقة (`derive_key`).
- التجزئة (`GCM tag`) تكشف أي عبث بالمحتوى.
- checksum (SHA-256) للتحقق من سلامة الملف.
- المفتاح الرئيسي يُخزَّن خارج قاعدة البيانات في `.env`.

## المصادقة

- **JWT** مع:
  - تدوير رمز التحديث (rotate refresh tokens).
  - إدراج الرموز الملغاة في القائمة السوداء (blacklist).
  - عمر قصير لرمز الوصول (30 دقيقة افتراضياً).
- **bcrypt (12 جولة)** لتخزين كلمات المرور.
- **قفل الحساب** بعد 5 محاولات فاشلة.
- تتبع **الجلسات النشطة** مع إمكانية إنهائها عن بُعد.

## الحماية من الهجمات

| الهجوم | الإجراء |
|--------|---------|
| Brute force | تحديد معدل (rate limiting) + قفل الحساب |
| CSRF | JWT (لا يعتمد على كوكيز) + CSRF middleware |
| XSS | رؤوس أمان + CSP + تعقيم المدخلات |
| SQL Injection | ORM من Django (معلمات مُعَدَّلة) |
| Clickjacking | `X-Frame-Options: DENY` |
| Sniffing | HTTPS + رؤوس أمان |
| Replay | تواقيت JWT + تدوير الرموز |

## سجل التدقيق

- تسجيل كل العمليات الحساسة: عرض، تحميل، مشاركة، حذف، تسجيل دخول.
- غير قابل للتعديل من لوحة الإدارة (منع الإضافة/التعديل).

## إدارة المفتاح

- يُنشأ عبر `scripts/generate_key.py`.
- يُدوَّر عبر `scripts/rotate_keys.py`.
- يُنسخ احتياطياً مع قاعدة البيانات عبر `scripts/backup_db.py`.

## قيود معروفة (لتطوير الإنتاج)

- تشفير من طرف الخادم فقط؛ يمكن إضافة تشفير من طرف العميل (E2E) لاحقاً.
- تطبيق MFA (2FA) عبر `pyotp` موجود في النموذج لكن يجب ربطه بالواجهات.
